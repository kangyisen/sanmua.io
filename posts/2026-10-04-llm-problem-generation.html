LLM Agent 自动出题：题面样例生成与向量查重

2026-10-04PythonAI编程

OJ 题目库靠人工攒，攒到一定阶段就会遇到：某个知识点覆盖不到、难度梯度断档。让 LLM 出题听着美，但直接说「给我出道题」，回来的往往是一段散文——没有结构化的输入输出样例、没有可信的边界数据、还可能和老题撞车。这篇讲我怎么把出题做成一条可信的流水线：约束结构化产出、用朴素解对拍校验、造标准测试数据、再用向量查重挡撞题。评测侧的隔离见OJ 判题沙箱。

整体流水线长这样

知识点 + 难度
      |
      v
 [LLM 生成] --Function Call 约束--> 题面/样例/边界
      |
      v
 [校验] 参考解跑样例自洽 + fuzz 对拍
      |
      +-- 不自洽 --> 重生
      v
 [查重] 题面+标签加权嵌入，cosine 比对老题
      |
      +-- 超阈值 --> 重生 / 转人工复核
      v
 向量入库，题目正式可评测

每一关都在拦住一种「看起来对、其实错或重复」的产物。

输入只有知识点和难度，产出必须结构化

问题在于自然语言题面没法直接进题库——评测需要可机读的样例和测试数据。所以我用 Function Call / JSON schema 把输出钉死成固定结构：

tools = [{
    "type": "function",
    "function": {
        "name": "save_problem",
        "parameters": {
            "type": "object",
            "properties": {
                "title": {"type": "string"},
                "description": {"type": "string"},
                "knowledge_tags": {
                    "type": "array", "items": {"type": "string"}
                },
                "samples": {
                    "type": "array",
                    "items": {
                        "type": "object",
                        "properties": {
                            "input": {"type": "string"},
                            "output": {"type": "string"}
                        }
                    }
                }
            },
            "required": ["title", "description", "samples"]
        }
    }
}]

这样模型不是「写作文」，而是被迫填一张表：题面、几组输入输出样例、知识点标签。后续解析入库就稳了。生成时强制它走函数调用，避免它在正文里写废话再附一段 JSON：

resp = client.chat.completions.create(
    model="deepseek-chat",
    messages=[
        {"role": "system", "content": "你是 OJ 出题专家，必须调用 save_problem 输出结构化结果。"},
        {"role": "user", "content": "知识点：滑动窗口；难度：中等。"},
    ],
    tools=tools,
    tool_choice={"type": "function", "function": {"name": "save_problem"}},
)
args = json.loads(resp.choices[0].message.tool_calls[0].function.arguments)

参考解从哪来：别让 LLM 解自己出的题

样例里的「期望输出」不能信模型嘴说的，得真算出来。这里最容易踩的坑是循环信任——用 LLM 出题、又用同一个 LLM 写参考解去校验样例，等于让学生自己给自己阅卷。我的原则是：

  • 优先确定性的朴素/暴力解：O(n^2) 暴力解逻辑简单、可手写，答案就是权威答案，哪怕慢也无所谓；
  • 实在要 LLM 生成参考解，必须把它丢进判题沙箱里，和一份手写朴素解做随机对拍，两者输出一致才信任。

标准造数流水线：generator + 暴力解 + 对拍 + fuzz

「边界数据」不是让模型脑补几句，而是一条造数流水线：generator 按约束随机造输入，暴力解算出期望输出，再和待测解对拍，同时专门覆盖边界：

import random

def fuzz_generate(case_count=200, max_n=1000):
    cases = []
    # 常规随机
    for _ in range(case_count):
        n = random.randint(1, max_n)
        cases.append(gen_random(n))
    # 必须覆盖的边界：0 / 1 / 最大规模 / 空集 / 重复值
    cases += [gen_empty(), gen_single(), gen_max_n(max_n),
              gen_all_same_value(), gen_zero_length()]
    return cases

def cross_check(brute_solver, candidate_solver, cases):
    for c in cases:
        if brute_solver(c) != candidate_solver(c):
            return False, c     # 不一致，打印这组 case 定位 bug
    return True, None

边界清单是关键：空输入、长度 1、最大规模、全是重复值、零长度数组——这些是模型样例里最容易漏掉、又最容易让正解 RE/WA 的角落。

向量查重：新老题像不像

题库大了之后最隐蔽的问题是撞题。我把新题的题面文本和知识点标签分别向量化，加权合并后和老题比对——单看题面容易被「换皮」骗过，标签重合能把同知识点变体也揪出来：

import numpy as np

def embed(text):
    r = client.embeddings.create(model="text-embedding-3-small", input=text)
    return np.array(r.data[0].embedding)

def weighted_vec(description, tags, w_tag=0.3):
    v_desc = embed(description)
    v_tag = embed(" ".join(tags))          # 标签拼成一句再嵌入
    v = (1 - w_tag) * v_desc + w_tag * v_tag
    return v / np.linalg.norm(v)           # 归一化

def cosine(a, b):
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

查重要先处理一个边界：新题库 existing_vectors 为空时，绝不能对空序列取 max——那会直接抛 ValueError。空库就直接放行：

def is_duplicate(new_vec, existing_vectors, threshold=0.9):
    if not existing_vectors:
        return False, 0.0          # 新题库，没有可比对象，直接放行
    best = max(cosine(new_vec, old) for old in existing_vectors)
    if best >= threshold:
        return True, best           # 太像，判疑似撞题
    return False, best

阈值（示例 0.9）不是拍脑袋定的，而是拿一批「已知相似 / 已知不同」的题对去画相似度分布，再在两条分布之间选一个分界点。过阈值的题我不直接毙掉，而是转人工复核——宁可让人多看一眼，也别让撞题上线。

备选方案与权衡

  • LLM 出题 vs 人工 vs 模板：人工质量最高但慢、覆盖窄；模板生成快但题型死板；LLM 铺量、工程校验兜底。我用「LLM 生成 + 暴力解对拍 + 向量查重」组合，让 AI 摊数量、工程守质量；
  • 查重用向量 vs 关键词：纯关键词抓得住字面重复，抓不住同义改写；纯向量反过来。两者互补，后续可再加一道标题/标签的关键词精确匹配。

核心经验：LLM 出题最大的风险不是「写得不好」，而是「看起来很对、其实错了或重复了」。用 Function Call 钉结构、用朴素解对拍守答案、用 fuzz 补边界、用加权向量挡住撞题——把生成从碰运气变成可验收的流水线。AI 负责铺开数量，工程负责守住质量底线。
